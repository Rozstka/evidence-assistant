# Evidence Assistant

A working REST assistant with document retrieval, cited answers and bounded LLM tool calling.
FastAPI, BM25-style lexical ranking, optional Ollama, SQLAlchemy, PostgreSQL and Docker.

## Architecture and behavior
`POST /documents` → content hash/deduplication → 800-character chunks with 100-character overlap → SQL storage.
`POST /chat` → lexical retrieval → optional LLM tool loop → schema/citation validation → persisted answer and tool trace.

- Demo mode returns **verbatim retrieved passages**, not generated reasoning. It runs without internet, credentials for an LLM or model downloads.
- Ollama mode can call one allowlisted read-only tool, `search_documents`, over at most two tool rounds and four model tool calls. A final schema-constrained answer must cite IDs from retrieved chunks.
- Unknown tools, invalid arguments, invented IDs, missing citations and provider failures produce explicit errors. There are no shell commands, arbitrary URL fetches, SQL generated by the model or write tools.
- No matching source means `insufficient_evidence`; the app does not invent an answer. `/search` exposes the ranked evidence and `/runs/{id}` exposes saved answers and traces.
- BM25 uses simple word tokenization and a conservative English plural heuristic. No embeddings, vector database or semantic-search claims. The corpus is capped at 100 documents of 20,000 characters each.

Citation validation checks provenance, **not semantic entailment**. A model can misinterpret a valid source. Read the returned source snippets.
Prompt-injection instructions in documents are treated as untrusted text; tool allowlisting enforces capabilities even if a model follows malicious text.

## Demonstration
With the server running and API_TOKEN loaded from `.env`:
```sh
python scripts/demo.py
```
The script ingests fictional policies, asks about refunds and express shipping, and asks an unrelated astronomy question to demonstrate abstention.
Example ingestion:
```json
{"title":"Synthetic returns policy","text":"Refunds take 5 business days after inspection.","synthetic":true}
```
Example chat:
```json
{"question":"How long do refunds take?"}
```
Use `/docs` to try both endpoints. Ingestion is idempotent for equal title and text. Different content creates a new document; document deletion and update/version management are future work.

## Deliberate MVP boundaries
Single operator and shared corpus; no arbitrary uploads/URLs, chat memory, private user documents, vector embeddings or production deployment claim.
Corpus ranking happens in application memory; PostgreSQL provides durable storage, not a full-text index in this version.

## Quick start — Docker with PostgreSQL
```sh
python3 scripts/configure.py
docker compose up --build -d
docker compose logs api
```
API: http://localhost:8001/docs. `GET /health` reports mode and database connectivity.
Open `.env` locally and paste `API_TOKEN` into the Swagger **Authorize** dialog. Do not share that value.
`docker compose down` stops the demo and retains its database volume.

## Local start — Python 3.12+, SQLite by default
```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
python scripts/configure.py
set -a
. ./.env
set +a
uvicorn app.main:app --host 127.0.0.1 --port 8001
```
Run setup only once; it intentionally refuses to overwrite `.env`. SQLite provides a quick local path.
For PostgreSQL set `DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DB` before starting.
Generated Compose passwords are hex, avoiding URL-encoding ambiguity. Supply a dedicated database.

## LLM mode
Default `LLM_MODE=demo` is deterministic and requires no model or paid API key; it is clearly labelled in responses.
For real model inference install [Ollama](https://ollama.com/), run `ollama pull qwen2.5:3b`, set `LLM_MODE=ollama`, and restart.
Default model: `OLLAMA_MODEL=qwen2.5:3b`. Local API: `OLLAMA_URL=http://localhost:11434`.
Compose connects to host Ollama through `host.docker.internal`; ensure it is reachable from Docker on your OS.
Do not expose an unauthenticated Ollama server to the internet.
The adapter uses Ollama's [chat API](https://docs.ollama.com/api/chat), schema-constrained JSON, timeouts and bounded output.
A small local model can still fail validation; the API returns 502 rather than treating unsupported output as valid.

## Tests
```sh
pytest -q
# Optional: use a disposable PostgreSQL database; tests DROP this project's tables.
TEST_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:5432/TEST_DB pytest -q
```
Tests cover both persistence paths, API validation, provider contract and failure handling.
GitHub Actions installs dependencies, runs SQLite and PostgreSQL tests, and builds the image.
`requirements.lock` pins resolved packages; `requirements.txt` lists direct dependency ranges.
See [SECURITY.md](SECURITY.md) for deployment boundaries and [reports](reports/) for measured smoke-test evidence.

## Reproduce the small regression evaluation

Run `python scripts/evaluate.py`. Reports explicitly identify the tiny synthetic sample; the measurements are not claims of production or medical accuracy.

Optional real-model check: `python scripts/live_smoke.py` uses an isolated in-memory database and the configured Ollama model, and saves the response and elapsed time. This is a smoke test, not a model benchmark.
